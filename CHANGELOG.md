# Changelog

All notable changes follow a simplified form of [Keep a Changelog](https://keepachangelog.com/).

## [2.0.0] - 2026-09-10

Version 2 turns the library from a collection of documented queries into tested detection content.
Every Sigma rule is now executed against synthetic events in CI, every ATT&CK and Atomic Red Team
reference is checked against pinned upstream data, and every derived artefact is generated from
playbook frontmatter.

### Added

- **Sigma unit-test suite**: 158 cases across 36 rule documents, asserting true-positive and
  false-positive behaviour for every rule. CI fails if a rule lacks either kind of case.
- **`scripts/sigma_eval.py`**: a Sigma evaluation engine written against the standard library
  (PyYAML is used only to read the rule files) — field modifiers, condition
  grammar, `event_count` / `value_count` / `temporal` / `temporal_ordered` correlations) with 42 of
  its own self-tests. It raises on unsupported constructs rather than passing them silently.
- **Pinned upstream snapshots**: `mappings/attack-reference.json` (Enterprise ATT&CK v19.2, generated
  from the MITRE STIX bundle, including Detection Strategies and their mutable elements) and
  `validation/atomic-index.json` (Atomic Red Team index). Both are regenerated by scripts in this
  repository and validated in CI.
- **Five new playbooks**: TH-021 AD CS certificate abuse (T1649), TH-022 NTLM coercion and relay
  (T1187, T1557.001), TH-023 Entra application consent and credential abuse (T1528, T1098.001),
  TH-024 inhibit system recovery (T1490), TH-025 Linux cron and systemd persistence (T1543.002,
  T1053.003).
- **Sigma correlation rules** for the analytics that are aggregate by nature: Kerberoasting breadth,
  NTLM and RDP fan-out, password-spray user counts, and a temporal correlation that pairs a spray
  with a credential-valid outcome.
- **YAML frontmatter** on every playbook as the single source of truth, plus `scripts/build.py`,
  which regenerates the README coverage table, coverage matrix, Navigator layer, legacy-ID map,
  Atomic coverage table, playbook index and documentation navigation. `--check` gates CI.
- **ATT&CK Detection Strategy alignment**: each playbook cites its DET and AN identifiers and maps
  ATT&CK's mutable elements to concrete tunable parameters in its own tunable-parameter table.
- **Purple-team validation tables**: Atomic Red Team tests by GUID with expected evidence, including
  explicit statements where no upstream test exists.
- New documentation: `TESTING.md`, `DATA_MODEL.md`, `ATOMIC_VALIDATION.md`,
  `DETECTION_STRATEGIES.md`, `ARCHITECTURE.md`, `ROADMAP.md`, and a MkDocs site.
- Repository tooling: `Makefile`, `requirements-dev.txt`, `.yamllint`, `.editorconfig`,
  `.gitattributes` (so GitHub reports the detection content rather than only Python), Dependabot,
  CODEOWNERS, and CI workflows for validation, the documentation site, and releases.

### Fixed

- **KQL term matching.** v1 used `has` / `has_any` for path fragments and command-line switches
  (`"\AppData\"`, `" -enc "`). `has` matches whole terms after tokenisation, so those predicates did
  not mean what they read as. All such comparisons now use `contains`, `endswith` or `matches regex`.
  Documented in [`docs/KQL_STYLE.md`](docs/KQL_STYLE.md).
- **TH-018 result-code handling.** v1 treated every non-zero Entra `ResultType` as a failed password.
  That over-counted disabled accounts (50057) and Conditional Access blocks (53003), and — worse —
  hid the finding that matters: 50074 / 50076 / 50079 / 500121 mean the password was **correct** and
  the sign-in stopped at MFA. Result codes are now classified explicitly and credential-valid
  outcomes escalate the alert.
- **TH-008 DNS rule.** v1 fired on every `TXT` query, which made it unusable in any estate with SPF,
  DKIM, DMARC or domain verification. The rule now requires an encoded-looking label and treats rare
  record types as an amplifier, with vendor-suffix filters.
- **TH-013 group matching.** v1 matched privileged groups by name, which fails silently on any
  non-English Windows installation. Matching is now by well-known SID and RID, with a French-locale
  regression test.
- **TH-009 Sigma condition.** `2 of (encoding, cradle, in_memory, hidden)` is not valid Sigma syntax.
  Found by the new evaluation engine during authoring and rewritten as `2 of sig_*`.
- **TH-004 / TH-006 exclusions.** Machine accounts and `ANONYMOUS LOGON` are now excluded from
  NTLM and RDP analytics, and LogonType 9 is covered for over-pass-the-hash tooling.
- Recovery destruction (`vssadmin delete shadows` and relatives) moved out of TH-014 into TH-024,
  matching ATT&CK's classification (Impact / T1490) and its very different response profile.

### Changed

- All 20 original playbooks rewritten with frontmatter, ATT&CK alignment tables, tunable-parameter
  tables, unit-test sections, purple-team validation, and expanded blind-spot analysis.
- KQL hunts now carry baseline companion queries, so thresholds can be derived from local data rather
  than inherited from this repository.
- `scripts/validate.py` extended from structural checks to frontmatter schema, ATT&CK fact checking,
  Atomic GUID verification, Sigma hygiene, tag-to-frontmatter consistency, KQL lint rules, fixture
  coverage, and a check for personal contact details in public files.
- ATT&CK mappings pinned to v19.2 with the Stealth / Defense Impairment tactic split and the
  T1562.001 → T1685 and T1070.001 → T1685.005 renumbering documented in a generated migration table.

## [1.0.0] - 2026-08-31

- ATT&CK Navigator coverage layer and data-source matrix.
- Deployment, telemetry, tuning, triage, validation, lab, and lifecycle documentation.
